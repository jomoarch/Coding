# cmp_s 测试数据

每个子目录是一组完整数据：`out.txt`（程序输出）、`ans.txt`（期望答案）、`config.toml`（可直接跑）。

```sh
cmp_s test/cmp/token_diff/config.toml
```

按键：`j` / `k`（或方向键）移动光标，`Enter` 展开或跳到下一个不同 token，`Shift+Enter` 上一个 token 或收回，
`c` 收回当前，`r` 全部收回，`q` / `Esc` 退出，`Ctrl+j` / `Ctrl+k` 只滚动视野。

| 用例 | 看点 | 实测结构 |
| --- | --- | --- |
| `identical` | BOM + CRLF + 行末空格/Tab + 文末空行，归一化后一致：直接退出，不进 TUI | 完全匹配，0 个不匹配行 |
| `first_line` | 只有第 1 行不同，进去光标就在它上面 | 1 个 `!`，y = 1 |
| `token_diff` | 情况 3 的主场：`[x / y]` 与 x 的补位、`null`、超长 token 的 `...` | 4 行，y = 1 / 3 / **12** / 2，第 4 行 read 侧是 null |
| `missing_middle` | 中间缺一行，看位置对齐的连带效果 | 3 行：line 3 `!`、line 4 `!`、line 5 `-` |
| `extra_tail` | 末尾多出两行 | 2 个 `+`（line 3、4） |
| `short_tail` | 末尾少两行 | 2 个 `-`（line 3、4） |
| `empty_output` | 输出是个 0 字节文件（程序崩了 / 没输出），期望有 3 行 | 3 个 `-`（output 0 行、expect 3 行） |
| `whitespace_only` | 情况 2：多空格、Tab 分隔、行首缩进；第 5 行**只有行末**空白不同，所以它不出现 | 4 个 `~`（line 1–4） |
| `wide_chars` | 中文 token 的截断与对齐、中文长行折行 | 3 行：`!`（长中文 token）/ `!` / `~`（长中文行） |
| `long_lines` | 300 字符的行、200 字符的缩进差异、250 字符的缺行 | 3 行：`!`（y = 1，token 超长被截）、`~`、`-` |
| `many` | 66 个不匹配行 / 每侧 200 行：滚动、两位数序号、三位数行号 | 66 个 `!`，每行 y = 1 |

## 两点注意

1. **输出文件会被就地规范化。** 比较器会把 `out.txt` 里的 BOM、行末空白、文末空行删掉并写回原文件。
   跑过一次 `identical` 之后，`out.txt` 会从 26 字节变成 11 字节（内容变成 `1 2 3\n4 5 6`）。
   原始字节是：

   ```
   ef bb bf 31 20 32 20 33 20 20 0d 0a 34 20 35 20 36 09 0d 0a 0d 0a 20 20 0d 0a
   ```

   `whitespace_only/out.txt` 同理，跑一次会少 4 字节（3 个行末空格 + 文末换行）。

2. **`missing_middle` 体现的是位置对齐语义。** 第 3 行缺掉之后，第 4 行不会被认成"整体前移"，
   而是逐行都不匹配，并在末尾多出一条 `-`（只在 expect 里存在）。这是当初选定的算法，不是 bug。

退出码：一致 `0`、不一致 `1`、配置或 IO 出错 `2`。
